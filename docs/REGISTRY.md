# 需求登记与判断依据（REGISTRY）

> 这份文件的用途只有一个：**X 改版后，先判断「坏的是哪个需求」，再决定「值不值得修、怎么修」**。
>
> 排序原则：**以我们的需求为主，以 X 的改版规律为辅**。
> 需求优先级的依据是「没有它就不叫映间」，不是「X 改它的频率」。
> X 的规律只用来决定**实现方式与兜底强度**，不用来调整需求本身。
>
> 与其它文档的分工：本文答「该不该做、做到什么强度」；`README.md` 答「这一版具体怎么做的」；
> `src/content/sel.ts` 是锚点的唯一代码来源；`src/content/probes.ts` 是本文第六节的实现。

## 一、需求登记

优先级定义：
**P0** = 关掉就不是这个皮肤；**P1** = 皮肤的语言，缺了会明显「不像」；**P2** = 增强，允许失效或降级；**P3** = 可选，失效就接受。

| 号 | 需求（我们的话） | 优先级 | 可调项 | 现在的实现锚点 | 锚点稳定级 |
|---|---|---|---|---|---|

| **R2** | 卡片化：每条推文独立成块、格间留缝、组内补线、裁切对齐 | **P0** | `cardFeed` | `ul > li[data-index]`、`article`、`clip-path: inset()` | S2（数值耦合最弱） |

| 级 | 含义 | 典型 | 寿命 |
|---|---|---|---|
| **S1** | 语义 / 行为，X 自己也依赖 | `main` `article` `nav` `role` `aria-label` `href` 里的 status id、CDN 路径 | 长 |
| **S2** | 变量 / 结构判据 | `--x-main-column-width`、`night_mode`、祖先遍历、「含 tweetText」 | 中 |

## 二、失效只有三个根因

15 次修补（0.2.0 → 0.2.15）全部落在这三类里，没有第四类。

| 根因 | 已发生实例 | 为什么会反复 | 判断规则 |
|---|---|---|---|
| **① 找不到**<br>锚点消失 / 改名 | 0.2.0 全量 testid 迁移；0.2.5 媒体；0.2.12 附 浮层 `role`；0.2.15① `text-brand`、③ 嵌套 `article` 归零 | X 用构建哈希命名并频繁换渲染方式；灰度期新旧两套并存 | 按第五节降级顺序换锚点；降到第 5 级以下必须配探针 |
| **② 量不对**<br>两个数值耦合 | 0.2.2/3 外壳 1280 vs 视口；0.2.9 的 1024 外壳 + `overflow-x-clip`；0.2.11 裁到字上；0.2.14 我们裁 15 + X 补 12；0.2.15② 操作栏 600 | 我们的量（裁切/留白/宽度）与 X 的量（padding / max-width）叠加，任一方动就错，且**不抛错** | 能读 X 的量就读（变量、computed），读不到就集中成一处常量；禁止散落魔法数 |
| **③ 盖不住**<br>层叠 / 优先级 | 0.2.8 `opacity` 盖住半透明；0.2.10 class `invisible` 输给内联 `visible`；0.2.13 `box-shadow` 不占盒被下一格盖；0.2.1 React 冲掉内联 | 同一属性有多个来源；内联 > 样式表 > 继承；绘制层与布局层混用 | 加优先级、补第二个属性（`visibility` + `opacity`）；**不要靠换选择器碰运气** |

推论：修 bug 的第一句话应该是「这是哪一类」，不是「这条选择器怎么写」。

## 三、决策矩阵

行 = 我们的优先级，列 = 锚点稳定级。**矩阵只回答「兜底强度」，不回答「要不要这个需求」。**

| 优先级 ↓ / 锚点 → | S1 语义行为 | S2 变量 / 结构判据 | S3 类名 / 内联值 | S4 只剩值 |
|---|---|---|---|---|
| **P0** | 直接写，声明式 | 写 + **必须有探针** | 写 + 第二锚点 + 探针 + README 记症状 | 禁用，当轮迁走 |
| **P1** | 直接写 | 写 + 探针 | 允许，但必须能降级 | 立即迁走或删 |
| **P2** | 直接写 | 允许 | **允许失效，不做兜底** | 删掉 |
| **P3** | 直接写 | 允许 | 允许 | 删掉 |

两条已发生的推论，用来校验矩阵是否可信：

- **0.2.4 去广告删得对**：P2 + 锚点消失 ⇒ 应删。当时用启发式兜底（「无 article 即杂物」）配合虚拟列表复用，把正常推文整条吃掉，正是违反此表。
- **R6 是唯一「P1 + S4」的需求**，所以它是全项目唯一必须「心跳重拍」的项，不能只写一次。

## 四、症状索引

用户报问题的第一句话，决定先查哪里。

| 用户说 | 根因 | 需求 | 首查一处 |
|---|---|---|---|
| 「像没装一样」 | ① 全局 | — | 扩展是否启用 → `main` 是否存在 → `dataset.xmErr` |
| 「右边被截断」 | ② | R1 | 外壳 `max-w` / `overflow-x-clip` / 我们补的 `padding-left` |
| 「还有圆角」 | ① | R3 | 引用卡、媒体两条判据各自命中数 |
| 「颜色没变」 | ①（值） | R6 | 页面内 `rgb(29, 155, 240)` 计数是否归零 |
| 「字被切 / 贴着边」 | ② | R2 | 我们的裁切量 − X 自带的 padding |
| 「按钮位置不对」 | ② | R1 | `role="group"[aria-label]` 的 `max-width` |
| 「多一条线 / 截图脏」 | ③ | R7 | 吸顶层的 `visibility` / `opacity` |
| 「间距忽大忽小 / 页面抖」 | ③ + 时序 | R2 | 标记是否幂等、是否有值比较 |

## 五、锚点降级顺序（换锚点时按此逐级试）

1. **语义标签**：`main` `article` `nav` `aside` `header`
2. **变量**：X 自己还在用的 CSS 变量（`--x-main-column-width`、`--x-sidebar-expanded`）。判据是「X 的样式表里还引用它」；已被算成字面量的变量（`--color-brand`）不算。
3. **值 / 行为**：CDN 路径（`pbs.twimg.com/media`、`/card_img`、`/profile_images`）、`href` 里的 `/status/<id>`、`data-post-avatar`
4. **结构遍历**：从特征元素出发沿祖先链走，走到边界（`article` / 主栏）就停；不写固定层数
5. **类名片段**：`[class*="origin-[var(--transform-origin)]"]` 这类。用之前先数命中数，并接受它下次就失效
6. **旧值**：`data-testid`（新版已基本归零）、内联 `rgb(...)`。只用于「按值改写」，且必须心跳重拍

⛔ 越过第 5 级还不加探针，等于埋一颗静默炸弹：样式照注入、一条不命中、控制台无报错。

## 六、探针清单

实现见 `src/content/probes.ts`，面板「诊断」小节实时显示。**探针只做锚点计数与条件判据，不改任何样式。**

| id | 需求 | 判据 | 正常 |
|---|---|---|---|
| `R1-1` | R1 | `main` 存在 | ≥1 |
| `R1-2` | R1 | 右栏 `aside` 或 `[data-testid="sidebarColumn"]` | ≥1 |
| `R1-3` | R1 | 左导航 `nav[aria-label="主要"]` 或 `header[role="banner"]` | ≥1 |
| `R2-1` | R2 | `cells()` 命中（旧 `cellInnerDiv` / 新 `li[data-index]`） | ≥1 |
| `R2-2` | R2 | `tweets()` 命中（旧 `article[data-testid="tweet"]` / 新 `article`） | ≥1 |
| `R2-3` | R2 | 卡片模式开启时，`cells()[0]` 的 `clip-path` 不是 `none` | 真 |
| `R3-1` | R3 | 引用卡若存在（嵌套 `article` 或 `role=link` 含 tweetText），圆角必须为 0 | 真（无引用卡时跳过） |
| `R3-2` | R3 | 页面上若存在正文图（`/media/`），其外层圆角必须为 0 | 真（无图时跳过） |
| `R6-1` | R6 | 设置色 ≠ X 蓝时，**可见**元素的品牌色载体为 0（连续 3 轮才算，见约束 5） | 真（用默认蓝时跳过） |
| `R8-1` | R8 | 状态链接 `a[href*="/status/"]` 存在 | ≥1 |

五条设计约束：

1. **条件判据必须能「跳过」而不是「报红」**。纯文字流没有图、时间线没有引用卡都是正常状态，报红就等于制造假警报，探针会被无视。
2. **只查「从有变 0」，不查样式值的美丑**。值不对是主观判断，锚点归零是客观事实。
3. **结果写 `document.documentElement.dataset.xmProbe`**（形如 `R2-1,R3-1`），面板、脚本、排查都能直接读。
4. **⛔ 探针必须走 `sel.ts` 的兼容层，不许自己写锚点。** 2026-11-25 实测踩到：X 在详情页跑的是**旧版结构**（`cellInnerDiv` 21 个、`article[data-testid="tweet"]` 11 条、新版 `li[data-index]` 为 0）。初版探针只写了新版选择器，功能明明正常却报 `R2-1` 异常 —— 一个会假警报的诊断比没有诊断更坏，它会教会人忽略红色。同理，R6 初版数到了详情页里一个 `0×0` 的隐藏节点（`color: rgb(29,155,240)`），也必须过滤掉不可见元素。
5. **值级判据要带连续确认（`confirm`），结构级判据不带。** R6 查的是内联字面量颜色：X 新渲染的节点先带品牌蓝，等下一次 `paintBrand` 补拍（≤0.8s）才换色，单轮采样必然偶发假红（实测首页：第 3 秒红、第 4.2 秒绿）。R6 设 `confirm: 3`（≈9s），其余保持 1 轮。换路由时计数清零，避免跨页带账。**判据抖动不是判据失效，但必须先消除抖动，否则红色会失去意义。**

## 七、三条硬规则

1. **一条规则只归属一个 R 号**。跨需求共用的锚点必须进 `sel.ts`；`styles.ts` 里现存的 53 处旧锚点（`primaryColumn` 33 / `cellInnerDiv` 20）是唯一历史债，清理要整批做，不许一条条改。
2. **数值不写死**。能读 X 的变量就不写常量；读不到就集中到一处，并在注释里写明「这个数是从哪量出来的」。
3. **P0/P1 的每条规则必须配探针**。没有探针的规则 = 随时会静默死亡。15 次失效里没有一次抛错，全是「注入成功、命中为零」。
4. **探针和样式共用同一套锚点**。探针自己另写选择器，等于在兼容层之外再造一个真相来源；X 灰度切版时会出现「功能正常、探针报红」——2026-11-25 已发生一次（详情页跑回旧版 `cellInnerDiv`）。探针只准调 `sel.ts`，样式只准写「旧 + 新」双份。
5. **不假设「新版就是当前版」**。X 按路由 / 账号灰度，同一个浏览器里首页与详情页可能跑不同结构。任何新锚点落地时，都要在**首页 + 详情页 + 搜索结果页**三种路由上各数一次命中。

## 八、X 改版后的处理流程

1. **看诊断**：面板 →「诊断」，读哪几个 R 号变红。没红的说明大概率不是锚点问题。
2. **归因**：对着第二节定根因（找不到 / 量不对 / 盖不住）。
3. **定强度**：对着第三节矩阵，决定是「直接修」「加兜底」还是「允许失效」。
4. **改**：按第五节降级顺序换锚点；逐条量像素，不许凭观感。
5. **登记**：在 `README.md` 补当轮小节（症状 → 真因 → 改法 → 实测值），并回填本文第四节的症状索引（新的症状要加进去）。

> 顺序不能反：先定根因再改代码。反了就变成「试一条选择器看看行不行」，那正是 0.2.0 之前的状态。
